The source archive has 885 regular files: 205 SVG, 84 adjacent deterministic
resource SVG-gzip copies, 205 PDF, 205 full-size PNG, and 186 thumbnails. The
browser tree has 801 files because every one of the 205 SVGs is stored exactly
once as an explicit `.svg.gz`; raw SVGs are absent. Thirty-one thumbnails are
provided for each projection.

The sorted `SHA256SUMS` file covers 804 payload objects. With the manifest and
last-written `release.json`, the completed prefix has 806 objects. Absence of
the marker means the prefix is incomplete, regardless of any other files.

## Browser delivery

| Object class | `Content-Type` | `Content-Encoding` | Cache and access |
| --- | --- | --- | --- |
| `tree/*/svg/*.svg.gz` | `application/gzip` | absent | public-read; one-year immutable |
| `tree/*/thumbnail/*.png` | `image/png` | absent | public-read; one-year immutable |
| `viewer.html` | `text/html` | absent | public-read; one-year immutable |
| PDF, full PNG, package, and metadata | inferred from filename | absent | public-read; one-year immutable |

The six documentation grids embed only the 480-pixel S3 thumbnail PNGs. A
selection opens `viewer.html?asset=<projection>/svg/<name>.svg.gz`. The viewer
validates the nested path, fetches it at the same origin, and streams the
response through `DecompressionStream("gzip")`. It offers both compressed and
decompressed downloads. This avoids loading multi-megabyte SVG or 4K PNG data
for contact-sheet display.

## Build, validate, and publish

The builder accepts only the tagged recovery archive, validates the exact
projection/format inventory, round-trips every gzip member to its source SVG,
and creates a new staging directory rather than modifying an existing one:

```sh
scripts/build-generated-assets-s3-release.sh
scripts/upload-generated-assets-s3-release.sh --validate-only
```

An authenticated dry run uses an empty temporary rclone configuration and
credentials entered silently through `/dev/tty`:

```sh
scripts/upload-generated-assets-s3-release.sh
```

The applied release requires exact destination confirmation, uploads one SVG
gzip and thumbnail pilot, checks anonymous bytes and HTTP metadata, publishes
general objects and compressed SVGs in separate phases, verifies all payload
objects, writes `release.json` last, and optionally reads every stored object
back:

```sh
scripts/upload-generated-assets-s3-release.sh --apply --verify-download
```

The uploader uses `rclone copy --checksum --immutable --check-first`; it never
uses `sync` or `move`. Unexpected pre-existing keys are rejected and nothing
is deleted. Credentials are unset before report production.

## Active Archive report and delivery

After a successful applied run, the uploader builds the canonical three-page
Devastation Pacific report titled **cartofreako v13 checked in to UCB Active
Archive Object Storage**. The tracked source template is
`docs/releases/v13-active-archive-report.html.in`; generated delivery files
are:

```text
reports/cartofreako-v13-ucb-active-archive-check-in.html
reports/cartofreako-v13-ucb-active-archive-check-in.pdf
```

The builder checks the Active Archive document-kind marker, exact title,
tagged three-page US Letter structure, embedded/subset Atkinson Next/Mono
fonts, Unicode maps, extracted evidence text, and rendered QA pages. It never
selects a generic `deposit-report.pdf`.

The uploader then opens that exact PDF in the desktop mailer, addressed to
`b.dekosnik@gmail.com` and `abigail.dekosnik@gmail.com`, with the report title
as the subject. It does not claim delivery merely because a composer opened;
the operator must confirm that the message was sent. A headless operator can
use `--skip-report-email`, but that explicitly leaves notification outside the
upload run and must be recorded in the release notes.

## Immutability

Never repair or replace bytes under `cartofreako/v13/` after its completion
marker is public. Corrections require a new generated-assets version and S3
prefix. The historical `cartofreako/v12/` release is likewise unchanged.
